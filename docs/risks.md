# Риски

## Активные

**STARTED/DONE статусы захардкожены.**
Если в Jira-проекте используются нестандартные названия статусов, `started_at` будет `None` у всех задач → Cycle Time и Time to Market = 0. Временное решение: добавить статус в `STARTED`/`DONE` в `server/metrics.py` вручную. Долгосрочно — вынести настройку в конфигурацию.

**SQLite не масштабируется горизонтально.**
Один процесс записи, нет репликации. Этого достаточно для одного экземпляра; для нескольких экземпляров потребуется миграция на PostgreSQL.

**Один процесс, нет корректного завершения активных запросов.**
`server.py` не обрабатывает сигналы. При `Ctrl+C` в середине длинного Jira-запроса — запрос обрывается, снапшот не сохраняется. Некритично — следующий запуск начнёт с нуля.

**Процессы одного системного пользователя находятся в доверенной зоне.**
Локальная модель аутентификации защищает от других пользователей ОС при корректных правах файлов, но не изолирует процессы того же пользователя. Для более сильной границы нужен отдельный пользователь ОС или контейнер.

**Старый SQLite-файл может оставаться во внутренних refs GitHub.**
История основных веток `main` и `dev` очищена 25 ноября 2026 года, текущие файлы игнорируются, а CI запрещает новые runtime DB и секреты. Служебный `refs/pull/1/head` и кэш GitHub могут сохранять старые объекты; полностью удалить их обычным force-push нельзя. Если содержимое станет чувствительным, потребуется обращение в GitHub Support и ротация затронутых секретов.

## Снятые риски

~~Нет постоянного хранилища~~ — реализовано: SQLite с неизменяемыми снапшотами.
~~Нет запуска по расписанию~~ — реализовано: `server/scheduler.py`, фоновый поток, `SYNC_INTERVAL_SECONDS`.
~~История теряется при очистке браузера~~ — история хранится в SQLite, localStorage больше не используется для истории.
~~TypeScript/Node.js версионные конфликты~~ — стек переведён на Python stdlib.
~~n8n как точка отказа~~ — n8n удалён, сервер самодостаточен.
~~Legacy `/webhook/sync-report` блокировал HTTP-поток~~ — legacy `server_app.py` удалён; актуальный `POST /sync` возвращает 202 и выполняет ингест в фоне.
~~Session token был публично доступной anti-CSRF capability~~ — добавлен обязательный `ADA_ACCESS_TOKEN`, ограничение попыток входа и HttpOnly-сессия в памяти; все endpoints данных и синхронизации требуют аутентификацию.
~~Учётные данные и конфигурация источника хранились в localStorage~~ — браузер получает только публичные поля профилей и отправляет их ID.
~~HTTP и планировщик запускали загрузку разными путями~~ — оба используют общую ограниченную очередь; Sync All принимается атомарно.
~~Частичные Jira/Trello данные могли попасть в снапшот при достижении лимитов~~ — лимиты истории и общий дедлайн завершают загрузку без записи.
~~Учётные данные Jira можно было отправить на произвольный `baseUrl`~~ — разрешены только HTTPS `*.atlassian.net` и точные хосты из `ADA_ALLOWED_JIRA_HOSTS`.

~~Hard cut Telegram-сообщений~~ — реализован умный чанкинг.
~~Case-sensitive статусы (BUG-S01)~~ — исправлено, все сравнения через `.lower()`.
